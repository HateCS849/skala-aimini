# 아키텍처 결정 기록

작성일: 2026-10-21. 결정은 현재 코드의 선택과 한계를 설명하며 미구현 기능을 구현했다고 표시하지 않는다.

## ADR-001: 브라우저에서 관찰한 요청에 장애 주입

- 문제: 서비스 소스 전체를 수정하거나 배포하지 않고 실패 대응을 확인해야 한다.
- 대안: 실제 인프라 Chaos 실험, 서버 Mock 전면 교체, 브라우저 계층 주입.
- 결정: 같은 출처에서 실제 관찰한 API와 파일에 Playwright route·DevTools로 장애를 주입한다.
- 이유: 작은 로컬 프로젝트에서도 반복·격리 가능한 사용자 관점 실험을 만들 수 있다.
- 결과: 화면 대응과 HTTP 성능은 확인하지만 실제 DB 장애·서버 재시작·외부 호출의 트랜잭션 위치를 자동 입증하지 않는다. 그 범위는 별도 구조 모델 또는 실제 서비스 어댑터가 필요하다.

## ADR-002: LLM은 계획·행동, 판정은 코드와 재현

- 문제: 모델이 그럴듯한 의견만으로 결함을 확정하면 오탐과 재현 실패가 발생한다.
- 대안: LLM 단독 판정, 고정 스크립트만 사용, 역할 분리.
- 결정: 계획·다음 행동을 모델이 선택하되 허용 후보를 JSON enum으로 제한한다. 판정은 계약 코드, 확정은 새 브라우저의 같은 API·장애 조건 재현으로 수행한다.
- 결과: 증거 추적성이 좋아지지만 문구·상태 기반 규칙의 표현 의존성은 남는다. 복잡한 성공 조건과 서버 데이터 중복 여부는 서비스별 검증기가 필요하다.

## ADR-003: 누락 검증과 제한 재계획

- 문제: 초기 AI 계획은 같은 유형에 예산을 쓰면서 중요한 유형을 누락했다.
- 대안: 모델에게 무제한 재시도, 규칙만 사용, 제한 재계획과 규칙 보완.
- 결정: 관찰 후보의 유형을 검사하고 기본 1회 재계획한다. 이후에는 규칙 보완임을 표시한다.
- 결과: 예산 내 유형 보장을 강화하지만 모델 호출·지연이 늘 수 있고, 규칙 보완을 AI의 독자적 발견으로 주장할 수 없다. 예산 밖·실제 주입 실패는 부분 완료로 남긴다.

## ADR-004: 저장 스냅샷을 SSE로 전달

- 문제: 긴 에이전트 실행에서 polling보다 즉각적인 진행 확인이 필요하다.
- 대안: polling, SSE, WebSocket·메시지 브로커.
- 결정: 단방향 진행 기록에 SSE를 사용하고 SQLite 스냅샷 해시로 재연결·중복 처리를 단순화한다.
- 결과: 별도 브로커 없이 동작한다. 모든 중간 상태의 전달 보장은 없으며 큰 스냅샷의 반복 전송과 다중 사용자 확장성은 향후 과제다.

## ADR-005: 로컬 단일 프로세스와 제한 동시 실행

- 문제: 여러 브라우저·모델을 한 머신에서 동시에 실행하면 실측 간 간섭과 자원 경쟁이 커진다.
- 결정: 브라우저 점검은 서버 전체 슬롯(`CRASHCUSTOMER_BROWSER_SLOTS`, 기본 2)으로 제한한다. 서로 독립인 장애 시나리오는 점검별 동시 실행 수(`scenario_concurrency`, 기본 2·최대 4)만큼 병렬 실행하고, 하나가 실패하면 나머지를 취소한다. 부하 요청·로그·계측도 필요한 범위에서 병렬화한다. 일반 JS 프론트와 FastAPI로 빌드 의존성을 줄인다.
- 근거: 동시 2개에서 장애 주입 단계 1.9배, 3개에서 2.5~2.7배 단축, 재현율·오탐 변화 없음(`docs/evaluation-concurrency-20261021.json`). 개별 시나리오는 자원 경쟁으로 약간 느려진다.
- 결과: 로컬 재현과 구현 설명은 단순하지만 stateless Worker·분산 부하·다중 사용자 권한 관리는 제공하지 않는다. PDF의 신규 과제에 기존 프론트 구조 전체를 복제해야 한다는 명시는 없어 현재 범위에 맞춰 선택했다.

## ADR-006: 컨텍스트 축소의 비용과 정확도를 함께 측정

- 문제: DOM·이력을 매번 그대로 전달하면 입력 토큰이 커진다. 무조건 줄이면 중요한 UI 맥락을 잃을 수 있다.
- 결정: 기본은 화면 텍스트 1,500자·최근 행동 5개이며 중복 ARIA를 제외한다. 평가용 full 조건을 따로 두고 같은 고정 관찰·목표·모델·허용 행동으로 비교한다.
- 결과: 입력 토큰·지연·허용 행동 선택 여부를 함께 기록한다. 작은 합성 폼의 결과를 긴 실제 서비스의 정확도·금전 비용 절감으로 일반화하지 않는다.

## ADR-007: 새 메인 감독과 역할별 계획·검증 AI

- 문제: 부하 실험기는 동작하지만 메인 AI가 실험 후 추천만 했으며 기존 브라우저 MCP 기능과 분리되어 있었다.
- 대안: 자유 생성한 API·셸을 AI가 실행, 규칙 실행기만 유지, 허용 후보를 선택하는 감독을 추가.
- 결정: 연구/MCP → 계획 AI → 경계 검문 → 기존 실행 작업자 → 독립 근거 검사/검증 AI → 제한 재계획 → 보고서 그래프를 새 메인에 통합한다. 최대 1~3회 안에 원래 요청 조건을 우선 검증하고, 동일 부하의 장애 해제·낮은 부하·독립 반복을 추가한다.
- 결과: 근거를 모으고 대조 실험을 선택하는 AI 행동이 실제 실행에 영향을 준다. 자유로운 API 탐색·임의 장애 생성은 포기하며 대상 앱의 명세·계측 연결은 사용자가 작성해야 한다. AI 실패/허용 후보 위반은 표시한 규칙 대체이며 전체 근거 판정은 partial이다.

## ADR-008: 실제 MCP 검색·검증과 수치 판정의 분리

- 문제: LLM이 지표 누락을 정상으로 해석하거나 근거 없는 원인을 생성할 수 있다.
- 결정: stdio MCP에서 Prompt·Runbook Resource·프로젝트 첨부 BM25 검색·실측 충분성 검증을 제공한다. 검증 AI는 코드가 확인한 문제/부족 근거 ID의 우선순위만 선택한다. MCP 판정은 로컬 검증기와 대조한다. 상태·표본·복원 누락을 complete로 만들지 않는다.
- 결과: 판정 재현성이 높아지는 대신 알려진 검사 규칙 밖의 결함은 놓칠 수 있다. BM25는 정확한 용어가 겹치지 않으면 근거를 놓친다. 가상 사용자 작업자 수를 AI 에이전트 수로 계산하지 않는다.

## ADR-009: 동일 입력 비용 비교와 맥락 손실을 함께 보고

- 결정: 새 계획 AI의 동일 고정 목표 3종×3회, 같은 후보·모델·스키마를 full/compact 교차 순서로 실행한다. compact는 반복된 전체 Runbook을 제외하고 검색 발췌를 줄인다. 전체 맥락 모드도 화면에서 선택할 수 있다.
- 실측: 평균 입력 1,636 → 822.67토큰(49.71% 감소), 평균 지연 2,754.71 → 1,557.11ms. 허용 계획은 양쪽 9/9이나 동일 실험 선택은 3/9쌍이다.
- 결과: 입력량 감소와 계획 일치/진단 정확도 보존은 별개의 주장이다. 이 측정으로 정확도·금전 비용 절감을 주장하지 않는다. 모델 캐시·장비 상태·작은 입력 집합의 영향도 남는다. 어떤 모드에서도 대상·최대 부하·원래 조건 검사 의무를 지킨다.

## ADR-010: LangSmith SDK 로컬 추적을 기본으로 유지

- 문제: 역할별 추적과 평가 자료가 필요하지만 프로젝트 문서·프롬프트의 외부 전송 범위를 확정하지 않았다.
- 결정: 실제 LangSmith RunTree SDK로 감독과 역할별 span을 구성하고, SDK post 없이 로컬 JSON을 저장한다. 실험 ID·역할·상태·경과·집계만 추적에 포함한다. 모델 입력/첨부 원문/인증은 추적에 넣지 않는다.
- 결과: 기본 환경에서 오프라인으로 경로·실패·시간을 확인할 수 있다. LangSmith 클라우드 화면과 실제 수신 검증은 제공했다고 주장하지 않는다. SDK 객체 생성과 클라우드 수신의 증거는 구분한다.

## ADR-011: 사용자 요청에 따른 합성 메타데이터의 클라우드 수신 검증

- 변경 계기: 사용자가 LangSmith 클라우드 수신 증빙을 요청했다.
- 결정: 전역 tracing을 켜지 않고, 완료한 전용 예제 실행의 역할·시간·상태·집계만 허용 목록으로 새로 구성해 전송한다. 새로운 클라우드 ID와 nonce를 부여하고 모든 하위 항목의 부모 관계·내용·시각을 실제 클라우드에서 다시 조회한다. 부분 수신은 성공으로 표시하지 않는다.
- 결과: 실제 메인 실행 13개 전송/조회 일치, LLM 역할 4개와 도구 역할 3개를 확인했다(`LANGSMITH_CLOUD_VERIFICATION_20261022.md`). 기본 로컬 추적과 이 승인된 메타데이터 내보내기를 구분한다. 프롬프트·첨부 원문을 LangSmith에서 재실행/분석하는 기능까지 제공한 것은 아니다.
