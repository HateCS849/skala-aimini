# PDF 평가 대비 개발·검증 현황 · 2026-10-22

이 문서는 새 메인 AI 감독 보완 이후의 현황이다. 기존 `REQUIREMENTS_AUDIT_20261022.md`는 보완 전 기록으로 보존한다. PDF 인쇄 p.9의 신규 주제 허용, p.12의 배점에 맞춰 정리했으며 획득 점수나 만점을 보장하는 채점표는 아니다. PPT·발표는 요청에 따라 제외했다.

## 기능 구현 완성도 · 30점의 판단 근거

메인 8730에서 `AI 감독`을 선택하면 목표·프로젝트 자료·기존 API 계획을 입력받고 다음을 실제 수행한다.

1. 근거 검색 작업자가 stdio MCP의 계획 Prompt, Runbook Resource, 프로젝트 첨부 검색 Tool을 호출한다.
2. 계획 AI가 허용된 실험 중 실행할 것을 선택하고 실제 근거 ID를 인용한다.
3. gate가 대상·최대 부하와 모델 응답 후보를 검증한다. AI가 URL·API·인증·요청 본문을 새로 만들지 못한다.
4. 실행 작업자가 기존 부하/정합성 LangGraph를 수행한다. 사용자별 세션, 실제 HTTP·계측, 취소·장애 설정 복원을 사용한다.
5. 검증 작업자는 MCP 충분성 판정과 로컬 검사 결과를 대조한다. 검증 AI는 실제로 관측한 문제·부족 근거의 우선순위를 선택한다. 표본·실제 상태·계측·보호 기능 근거가 부족하면 complete로 표시하지 않는다.
6. 감독은 남은 예산과 결과에 따라 낮은 부하·장애 해제 대조·독립 반복을 계획하고 실행한다. 최대 1~3회 안에 원래 요청 조건을 포함한다. 인증/사전 확인 실패는 부하 반복으로 우회하지 않는다.
7. 보고서는 원래 조건과 후속 대조의 판정·제한을 함께 보존한다. SSE는 작업자 실행과 AI 대기 동안 부모 실험을 계속 갱신한다.

실제 검증은 `agent-live-evidence-20261022.json`, 전체 보고서는 `agent-live-report-20261022.md`에 있다. 합성 앱의 로그인 지연·10명 동시 사용자·DB 풀 2개 조건에서 변경 전 독립 조회 영향이 관측되고, 변경 후에는 영향이 관측되지 않았다. 최신 실행은 원래 조건과 5명으로 줄인 대조를 계획·실행·검증했고, MCP 프로젝트 첨부 검색과 실제 로컬 Ollama 계획/검증 호출을 확인했다. 이전 장애 해제 대조의 증거는 `agent-baseline-control-evidence-20261022.json`에 보존했다. 이 수치는 실제 Hangari 운영 결과가 아니다.

최종 전체 회귀는 **212 passed, 1 warning, 30.51초**다(`cloud-tests-20261022.txt`). 경고는 기존 LangSmith SDK 메서드의 deprecation이다. 새 감독 관련 10개 검사와 클라우드 내보내기 관련 7개 검사를 포함한다. 화면에서 직접 제출한 `23e5033af3dd48a0a38d0a902c455865`는 설정한 1회 예산대로 실행·검증되었다(`agent-ui-evidence-20261022.json`). 이전 실행 `8cfa96f00e9141c8824ca3395ac77867`의 원래 실험/장애 해제 대조 화면에서 오류율 **94.9% / 0.0%**가 각각 표시되는 것도 확인했다. 브라우저 오류/경고는 관측되지 않았다.

실제 로컬 SDK 추적은 `agent-live-trace-20261022.json`에 있다. 감독 루트와 자식 12개(총 13개), 그중 계획·검증 역할 LLM span 4개를 보존한다. 이후 사용자 요청으로 허용된 합성 메타데이터를 클라우드로 전송해 **13/13개 수신·내용 일치**를 확인했다. 실제 조회 증거는 `langsmith-cloud-receipt-20261022.json`, 범위와 링크는 `LANGSMITH_CLOUD_VERIFICATION_20261022.md`에 있다.

## 기술 요소 반영 · 30점의 판단 근거

| PDF 요소 | 현재 적용과 증거 |
|---|---|

## 동일 입력 전후 실측 · 보너스 10점의 판단 근거

기존 대상 앱의 취약/개선 비교와 별개로, **새 메인 계획 AI 자체의 입력 최적화**를 측정했다.

- 같은 고정 목표 3종 × 3회, 각 full/compact 실행. 같은 후보 ID·모델·JSON 스키마·근거 집합을 사용하고 쌍별 순서를 교차했다.
- full: 전체 Runbook과 검색 발췌를 전달. compact: 반복된 전체 Runbook을 제외하고 검색 발췌 길이를 줄임.
- 원본 고정 입력 파일과 SHA-256, 18회 호출의 입력/출력 토큰·지연·응답을 보존했다.

| 실제 모델 호출 | 9 | 9 |
| 허용 후보·출처 ID 검증 통과 | 9/9 | 9/9 |
| 평균 입력 토큰 | 1,636 | 822.67 |
| 평균 출력 토큰 | 24.33 | 24 |

입력 토큰 **49.71% 감소**. 단, 동일한 실험을 선택한 쌍은 **3/9**이다. 이는 허용 계획 생성의 유효성을 유지했다는 범위의 결과이며, 진단 정확도나 의사결정의 동일성을 보장하지 않는다. 맥락 손실을 숨기지 않으며 화면에서 전체 Runbook 모드를 선택할 수 있다. 로컬 모델이므로 금전 비용 절감으로 환산하지 않는다.

## 한계·트레이드오프 · 20점의 판단 근거

- **자율성과 실행 통제:** AI는 허용된 실험만 고른다. 임의 서비스의 모든 행동·장애를 자동 발견하는 도구가 아니며 API 계획·계측·제어 어댑터 연결이 필요하다.
- **신뢰성과 비용:** 계획 AI와 검증 AI를 분리하면 모델 호출·대기 시간이 추가된다. 최대 실험 수는 전체 실행 수를 제한하며, 1회 실험 안의 변경 전후 대상은 순차 실행한다. 동일 키 반복 등은 독립 테스트 데이터를 사용한다.
- **근거 부족과 정상의 구분:** 표본·실제 상태·보호 기능 정상 기준·지표가 부족하면 partial/unverified다. 근거 complete와 서비스 무결함은 다르다. 풀 포화·대기만 관측되고 사용자 오류가 없는 대조 실험도 있을 수 있다.
- **RAG:** BM25는 단어가 겹치지 않으면 검색을 놓치고 첨부 문서가 오래되면 잘못된 맥락을 준다. 문서의 지시는 실행하지 않는다. 후보 ID 제한으로 문서가 임의 URL·명령 실행을 유도할 수 없게 한다.
- **압축:** 입력량·지연 감소와 의사결정 보존을 구분한다. 실제 선택 차이 6/9쌍과 전체 맥락 모드의 선택지를 제시했다.
- **추적:** 기본 SDK 로컬 추적과 명시적으로 선택한 합성 메타데이터의 클라우드 전송을 구분한다. 실제 수신은 확인했지만 프롬프트·첨부 원문을 전송하지 않아 클라우드에서 전체 입력으로 재실행하는 기능까지 제공하는 것은 아니다. 일반 실험의 자동 외부 추적은 비활성이다.
- **재현 범위:** 로컬 합성 앱·SQLite·전용 Redis에서 확인했다. 실제 Hangari/Spring/HikariCP, PostgreSQL 데드락, 배포 인프라 장애 전체를 검증한 것이 아니다. 자원 증가는 실제 45초 측정과 최대 1시간 설정을 구분한다.
- **운영 구조:** 실행 Task는 단일 서버 메모리에 남는다. 파일 기반 기록·SSE 재접속은 가능하지만 무상태 분산 Worker나 중단 지점 이어 실행은 아니다.

## 아직 완료로 표시하지 않은 것

- PPT·발표 20점: 요청에 따라 제외. 코드 설명과 질의응답 평가도 실시하지 않았다.
- Google Spread의 과제·계획·Git·결과 보고서 주소 등록: 실제 등록 여부 미확인.
- 실제 Hangari 연결을 통한 검증: 별도 대상 계약·실행 환경이 필요하다.

개발·실측·한계 설명의 근거는 보강했지만, 위 항목을 포함해 전체 점수나 만점을 확정했다고 표현하면 안 된다.
