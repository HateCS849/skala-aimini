# 배포 전 장애 실험 Runbook

## 로그인 지연과 DB 풀 · pool isolation login connection
외부 로그인 응답을 기다리는 동안 DB 커넥션을 보유하면 독립 조회까지 대기할 수 있다. 기준·장애·회복 단계의 HTTP 실패율과 P95, 실제 pool_active/pool_max/pool_pending을 함께 비교한다. 포화와 오류가 함께 관측되어도 트랜잭션 코드 위치까지 확정하지 않는다. 같은 인원에서 장애를 해제한 대조 실험(no_fault)과 낮은 부하(reduced_load)로 원인을 분리한다.

## 재시도 증폭 · retry external 429
논리 로그인 요청 수와 실제 외부 시도 수의 증가량을 비교한다. 낮은 동시 사용자에서도 시도/논리 요청 비율이 크면 재시도 정책을 검토한다. 전후 완료 요청 수가 다르면 총 호출 수만 비교하지 말고 증폭 비율을 제시한다. 계측이 없으면 재시도 횟수를 추정하지 않는다.

## 재고·주문·중복 · stock integrity idempotency
HTTP 200만으로 정합성을 보장할 수 없다. 초기 재고, 실제 주문 수, 고유 멱등 키 수, 최종 재고를 조회한다. 동시에 다른 키의 주문을 수행하고 같은 키도 반복한다. 요청이 전부 거절되거나 실제 상태가 누락되면 성공 판정을 보류한다. 독립된 테스트 데이터 범위로 반복(repeat)한다.

## Redis·DB 잠금 · cache lock
의존성 연결 실패와 사용자 요청 실패를 구분하고 대체 경로가 동작하는지 확인한다. 장애를 해제한 동일 부하 대조 실험으로 트래픽 자체와 의존성 장애를 분리한다. SQLite 쓰기 잠금은 PostgreSQL 데드락 재현의 근거가 아니다.

## 재시작·자원 증가 · restart memory heap soak
재시작은 소유한 예제에만 허용하고 실제 부트 ID 및 기준 데이터의 전후 상태를 비교한다. RSS, 힙, FD, 스레드의 충분한 시간 추세가 필요하다. 짧은 관찰이나 지표 누락은 미확인이다. 자원 증가 징후는 누수 원인 확정과 다르다.
